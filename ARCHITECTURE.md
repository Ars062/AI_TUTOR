# Architecture Documentation

## System Overview

A Flask-based web application that predicts residential property prices in Bengaluru, India and provides investment risk analysis. The system has two distinct components: an ML-based price predictor and a rule-based risk assessment engine.

---

## 1. Existing ML Pipeline

### Training Pipeline (in `banglore_home_prices_final.ipynb`)

```
bengaluru_house_prices.csv (13,320 rows × 9 columns)
        ↓
Drop columns: area_type, society, balcony, availability
        ↓
Drop NaN rows (13,320 → 13,246)
        ↓
Extract bhk from size column ("2 BHK" → 2)
        ↓
Convert total_sqft to numeric (handle ranges like "2100-2850")
        ↓
Compute price_per_sqft = price × 100000 / total_sqft
        ↓
Location dimensionality reduction: 1,287 locations → 241 (group ≤10 occurrences as "other")
        ↓
Outlier Removal (4 rounds):
  Round 1: Remove sqft/bhk < 300 (13,200 → 12,456)
  Round 2: Remove price_per_sqft outside mean ± 1 std per location (→ 10,245)
  Round 3: Remove higher-BHK with lower pps than lower-BHK mean (→ 7,331)
  Round 4: Remove bath > bhk + 2 (→ 7,253)
        ↓
One-hot encode location (240 dummy columns)
        ↓
Final: X = 7,253 × 243 features, y = price (Lakhs)
        ↓
Train/test split: 80/20, random_state=10
        ↓
LinearRegression(fit_intercept=False)
        ↓
Export: pickle model + columns.json
```

### Dataset

| Property | Value |
|---|---|
| Source | Kaggle: "Bengaluru House Price Data" |
| URL | https://www.kaggle.com/amitabhajoy/bengaluru-house-price-data |
| Raw rows | 13,320 |
| Raw columns | 9 (area_type, availability, location, size, society, total_sqft, bath, balcony, price) |
| After cleaning | 7,253 rows |
| Features | 243 (3 numeric + 240 location dummies) |
| Target | `price` in Lakhs of INR |
| Price range | ~5 to ~1,000+ Lakhs |

### Data Leakage Check

The pipeline has no data leakage:
- `price_per_sqft` is computed from `price` and dropped before training
- `size` is dropped after extracting `bhk`
- Location encoding uses train-time column set (columns.json saved separately)
- One-hot encoding is applied before train/test split (acceptable for categorical encoding)
- Outlier removal uses per-location statistics computed on full data before split — this is a minor concern but acceptable given the small dataset

## 3. Existing Preprocessing

### Price Prediction Model
- Drop: area_type, society, balcony, availability
- NaN removal: drop rows with any NaN
- Feature extraction: bhk from size, total_sqft to numeric
- Dimensionality reduction: locations with ≤10 occurrences grouped as "other"
- Outlier removal: 4 rounds (sqft/bhk, price_per_sqft per-location, BHK-level, bathroom)
- Encoding: one-hot encoding for 240 location categories
- No feature scaling applied (LinearRegression is scale-invariant)
- No normalization or standardization

### Risk Calculations
- No preprocessing — raw feature values used directly
- Price per sqft computed as `(price × 100000) / sqft`
- Market rate estimated as `(rent_per_sqft × 12) / 0.03` (3% yield assumption)

## 5. Existing Risk Calculations

All risk calculations are **rule-based** (deterministic formulas), NOT ML-based.

### Investment Risk Score (util.py:35-109)

Starting score: 5.0, adjusted by additive factors:

| Factor | Condition | Score Impact |
|---|---|---|
| Overpricing | price_per_sqft > market × 1.3 | +2.0 |
| Overpricing | price_per_sqft > market × 1.15 | +1.0 |
| Safety | safety < 5.0 | +2.0 |
| Safety | safety < 6.5 | +1.0 |
| Flood risk | flood == "High" | +1.5 |
| Flood risk | flood == "Medium" | +0.5 |
| Liquidity | liquidity == "Low" | +1.0 |
| Crime | crime == "High" | +1.5 |
| Crime | crime == "Medium" | +0.5 |
| Bath/BHK ratio | ratio > 1.5 | +0.5 |
| Space efficiency | sqft/bhk < 300 | +1.0 |

Score clamped to [1, 10]. Levels: Low (≤3), Medium (≤5), High (≤7), Very High (>7).

**Market rate formula:** `(rent_per_sqft × 12) / 0.03` — assumes 3% annual rental yield cap rate.

### Overpricing Detection (util.py:112-150)

```
price_per_sqft = (price × 100000) / sqft
market_estimate = (rent_per_sqft × 12) / 0.03
adjusted = market_estimate × (1 + (bhk-2) × 0.05) × (1 + (bath-2) × 0.02)
deviation = (price_per_sqft - adjusted) / adjusted × 100
```

Thresholds: >20% → Overpriced, >10% → Slightly High, <-20% → Underpriced, <-10% → Slightly Low, else → Fair

### Location Rating (util.py:153-200)

Reads directly from `location_risk_data.json`. Grades: A (premium), B (good), C (developing), D (emerging/high-risk).

### ROI Estimate (util.py:203-226)

```
monthly_rent = rent_per_sqft × sqft
rental_yield = (annual_rent / price) × 100
total_roi = rental_yield + appreciation_rate
payback_years = price / annual_rent
```

## 8. Existing Frontend Flow

1. On page load: `GET /api/get_location_names` populates location dropdown
2. User enters: sqft, BHK (radio), bath (radio), location (dropdown), expected price
3. "Estimate Price" button: `POST /api/predict_home_price` → displays price in Lakhs
4. "Get Risk Report" button: `POST /api/get_risk_report` → displays 4-card risk report:
   - Investment Risk Score (1-10 gauge)
   - Price Analysis (overpricing status + deviation)
   - Location Rating (A-D grade + breakdown)
   - ROI Estimate (rent, yield, appreciation, total ROI, payback)

## 10. Current Limitations

1. **Location risk data is synthetic** — not sourced from real crime, flood, or infrastructure statistics
2. **No input validation** — API accepts any values without bounds checking
3. **No error handling** — bare `except` clauses, no structured error responses
4. **No logging** — only `print()` statements
5. **No tests** — zero unit or integration tests
6. **No requirements.txt** — dependencies not documented
7. **Unused ML models** — investment_model.pickle and overpricing_model.pickle exist but are never used
8. **Undocumented feature mapping** — the 8 features expected by investment/overpricing models are unknown
9. **Hardcoded thresholds** — risk thresholds not parameterized or configurable
10. **No model versioning** — no way to track which model version is deployed
11. **No retraining pipeline** — notebook-based, not reproducible from command line
12. **Frontend hardcoded to localhost:5001** — not deployment-ready
13. **No rate limiting or authentication** on API endpoints
14. **3% yield assumption** in market rate formula is hardcoded and not configurable
